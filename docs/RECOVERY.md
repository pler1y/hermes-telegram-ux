# 升级、卸载与恢复

所有修改前应停止对应 Gateway，确保前台和后台任务都结束。安装器故意不处理服务管理，以支持不同账号、systemd 层级和容器环境；不要在 Gateway 或其他程序同时写配置时执行。

每次变更先备份原始配置、当前插件和安装管理记录，然后记录事务日志，再替换文件。配置与管理记录采用同目录临时文件加原子替换。发生同步错误会立即恢复本次变更前的状态。

断电或进程被强制结束后，下一次 install/uninstall 会拒绝继续。保持 Gateway 停止，使用原发行包中的 `install.py recover --hermes-home ...` 恢复。恢复命令不要求旧核心仍然兼容，因此核心升级后仍可卸载或恢复本插件。

如果配置在中断后又被其他程序修改，恢复命令不会直接覆盖；错误会指出本次备份目录。先将现有配置另外备份，再核对该目录的 `config.yaml` 和管理目录中的 `transaction.json`。保留这些新修改，完成合并后再进行恢复或寻求维护者帮助。不要公开上传原始备份。

首次安装基线不会被后续升级覆盖。正常卸载用首次基线恢复仍受管理的配置键，保留之后新增的其他插件、模型设置及个人修改；卸载不等于整份 config.yaml 回滚。如果首次安装时已有旧插件，卸载会恢复那个旧插件和当时的启用状态。

不要手工删除 `$HERMES_HOME/telegram-ux-installer/state.json` 或它引用的基线备份。没有管理记录的手工安装不能由此工具推断恢复点；它会报告未发现受管理的安装。

恢复配置后需要重启 Gateway，旧 Python 进程中已经加载的代码不会因磁盘文件变更而自动消失。老会话可能保留冻结的模型指令；使用 `/new` 开始新会话。
