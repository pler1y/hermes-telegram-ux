# 兼容边界

1.8.0 支持以下三套自动化验证基线；官方目录申请已提交，尚未获准收录：

| Hermes | 核心提交 | 验证范围 |
|---|---|---|
| 0.21.0 | `b499ab11fe8b081470e269f2fb27abae03000da5` | 回归、原生安装、注册及两种 ZIP 的生命周期 |
| 0.21.2 | `a84a2223f82c3d9906fd4a9d778a188774e7a08e` | 上述检查及官方 catalog admission validator |
| 0.21.2 | `436ec489854b7110b4c5506b1f52c514fa4c3ace` | 上述检查；另验证上游任务租约、停止及替换任务的回归 |

`plugin/compatibility.json` 为每套基线记录 23 个接口文件的 SHA-256，包括实际承载忙碌输入、后台完成和停止行为的 gateway mixin。运行环境必须完整匹配其中一套，不能混用不同基线文件。Git 提交号用于诊断；只修改目录条目、文档或其他未涉及文件的提交不再被单独拒绝。源码归档执行相同哈希检查。

这不是对任意 0.21.x 提交的支持承诺。被保护的文件发生变化时仍拒绝注册，需先检查差异并运行回归才能新增基线。CI 在每次 push/PR/手动运行时另检查当时的官方 main；没有后台自动更新兼容哈希。

兼容检查发生在安装前和 `register(ctx)` 注册前；失败不会先打上一半补丁。检查器不在插件发现线程导入 `gateway.run`，避免发现锁与网关导入相互等待。

公开接口包括 tools、hooks、middleware、系统提示区块和 Telegram platform handler。内部适配涉及消息入口、回合前及回合中的上下文压缩、长任务通知、忙碌输入回执、停止、后台完成消费、Telegram 发送与编辑、部分显示清理。内部接口没有跨任意版本的稳定保证。

运行期不修改 Hermes 源码文件。关闭插件并重启进程后，这些运行期适配消失。与修改同一入口的第三方插件同时使用尚未验证；重复安装进同一进程会明确报错。

Schema 中的 `_hermes_progress` 是展示元数据，在实际工具 hooks、审批和执行前移除。只对已支持的 OpenAI / Codex 简单参数结构启用 strict 转换；其他提供方保留原生结构并增加公开说明字段。可选参数的空占位会恢复为省略，原本合法的 null 保留。

提供固定中英文界面；模型生成内容通过所选语言的提示规范引导。群聊、话题与身份隔离有回归覆盖。此前完整实机记录来自 1.7.0 的私人聊天；本版本在新核心上的自动测试不等于新的 Telegram 实机验收，目前未声称在该核心上完成新的全流程实机验收。

官方原生 Git 安装及配置入口见 [NATIVE-INSTALL.md](NATIVE-INSTALL.md)。ZIP 管理与原生管理不能在同一安装记录上混用。

上游参考：[原生插件开发文档](https://hermes-agent.nousresearch.com/docs/developer-guide/plugins/)。安装行为以这里固定的核心源码和本项目测试结果为准，不把上游未来变化当作已兼容。
